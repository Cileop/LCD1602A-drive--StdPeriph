## 0. 结论摘要 / TL;DR

1. **根因 / Root cause**：初始化从未把控制器切进 4-bit 模式。代码三次发 `0x38`（=高半字节 `0x3`
   +低半字节 `0x8`），但正确序列是“三个单半字节 `0x3`，再一个单半字节 `0x2`，再 `0x28`”；
   代码里没有任何 `0x2x`。控制器停在 8-bit 模式，而后文所有命令又按 4-bit 发两次半字节，
   于是全部被误解释 → 花屏（与 `phenomenon.jpg` 现象一致）。
2. **接线位映射代码是对的**：`P0=RS / P1=RW / P2=E / P3=背光 / P4..P7=DB4..DB7`，代码用
   `0x01/0x02/0x04` 正好对应（`MyPCF8574.c:55-68`）。**但 `P3` 是背光，不是代码注释里的 CS/E**；
   背光高电平点亮，而代码所有字节 bit3 恒为 0，即背光永远不亮（除非模块根本没被写入、保持上电 0xFF）。
3. **0x27 地址正确**：板上是 `PCF8574T`（非 A），A0/A1/A2 由 10K 上拉到 VCC、SHORT 跳线接地，
   悬空=全 1 → 7-bit 地址 **0x27**（写字节 `0x4E`），代码 `0x27<<1` 正确。
4. 忙标志轮询（`MyLCD1602A.c:33-77`）是**永远返回“不忙”的死代码**（`&0x0F` 后再 `&0x80` 恒为 0，
   且读之前没有把 P4..P7 置高），所以 1.52 ms 清屏等待实际上没有实现。
5. 电源/对比度：模块与 LCD 逻辑电源都要求 **+5V**（照片接线也是 +5V）；V0 由板上蓝色电位器调，
   对比度电压 `VDD−V0 = 4.2~4.8 V @25℃`。3.3 V 供电会又暗又无对比度。

## 3. 4-bit 传送规则 / 4-bit transfer rule

1. 高半字节先送，低半字节后送，**各自带一次独立的 E 脉冲**（写：E 下降沿锁存）。
   依据：`1602A.pdf` p.9（DL=0 只用 DB7~DB4、需分两次）；`字符点阵液晶使用手册.pdf` p.8（每次传送的
   `TcycE/Pweh/Tdsw/Th` 时序）、p.9（写指令/写数据的 E 边沿真值表）。
2. 物理上只有 D7~D4 四位有效：`1602A.pdf` p.7（4-bit 时 D0~D3 脚断开）+ `原理图.pdf` p.1
   （J2 的 DB0~DB3 无连线）。
3. 拼字节时要先 `data & 0xF0`，再 `data << 4`；`RS/RW` 在两个半字节期间保持不变。

**为什么必须先 `0x3,0x3,0x3` 再 `0x2`**：上电时控制器处于 8-bit 模式且半字节相位未知。
`0x3`（高半字节）在 8-bit 模式下恒为合法的 Function Set（`DL=1`），连发三次可把状态拉回确定值，
与上电时它“卡在半个字节”无关；随后发单半字节 `0x2`（`DL=0`）才真正切入 4-bit，之后一个字节
必须发两次半字节。依据：`字符点阵液晶使用手册.pdf` p.14（三×`0x3` + 功能设置，间隔 4.1ms/100µs/40µs）
+ p.11–12（DL/N/F 定义）+ `1602A.pdf` p.9（两次传送）。canonical 写法即 `0x33, 0x32, 0x28`
（Hitachi HD44780U，不在 repo 内）。

## 5. 当前代码违反的要求清单 / Requirements the current repo code violates

1. **未进入 4-bit 模式**（最严重，决定一切）：`MyLCD1602A.c:13-18` 三次 `0x38` 每次发两个半字节
   （`0x3`+`0x8`），且全文**没有** `0x2`/`0x28`。要求见 `字符点阵液晶使用手册.pdf` p.14、
   `1602A.pdf` p.9。后果：控制器留在 8-bit，后续所有“两半字节”命令被误解析 → 花屏/无显示。
2. **清屏/归位后没有 1.52 ms 等待**：`MyLCD1602A.c:21-22` 把 `Delay_ms(15)` 注释掉，改用查忙；
   而查忙本身失效（见 3）。要求见 `字符点阵液晶使用手册.pdf` p.10、`1602A.pdf` p.8。
3. **忙标志读取实现错误**（`MyLCD1602A.c:33-77`）：
   (a) 读之前写 `0x06`，P4..P7 仍被驱动为 0，违反“准双向口作输入必须先为高”
   （`PCF8574中文手册.pdf` p.6 / `PCF8574.pdf` p.1）；
   (b) `Hdata &= 0x0F; Hdata &= 0x80;`（:60-62）使结果恒为 0，循环最多一轮就退出；
   (c) 4-bit 下 BF 在高半字节，且应连读两个半字节，代码只保留一次读且未用；
   (d) 全部 `MyI2C_ReceiveAck()` 返回值被丢弃，模块不在线也无声通过。
4. **背光从不点亮**：`P3` 是背光开关且 **P3=1 才亮**（`原理图.pdf` p.1：P3→R7 4.7K→Q1 8050 基极，
   C→LED K，E→GND）；代码所有字节 bit3=0。代码注释把 P3 说成 `CS/Enable`（`MyPCF8574.c:46-48`）是错的，
   E 实际是 P2。
5. **上电等待不足 canonical 40 ms**：只有 `Delay_ms(25)`（`MyLCD1602A.c:12`）。repo 内文档只要求
   >4.1 ms（`字符点阵液晶使用手册.pdf` p.14）或 15 ms（`1602A使用说明书.pdf` p.5），故属“低风险但
   不合原厂规范”，建议统一改成 40~50 ms。
6. **命令间无 37/39 µs 保证**：现在靠软件 I²C 极慢（每字节约 180 µs）偶然满足；一旦提高 I²C 速度
   （当前 `Delay_us(10)`，`MyPCF8574.c:109,131,153`），就会破坏 1.52 ms / 37 µs 要求。

**未违反（可保留）/ OK**：P0/P1/P2 = RS/RW/E 位定义；I²C 7-bit 地址 0x27；
高半字节先行、低半字节后行；`0x80/0xC0` 行地址；PB6/PB7 开漏 + 板上 4.7K 上拉；E 高电平 ≥2 µs（≥450 ns）。

## 6. 其他注意事项 / Notes

- **文档内互相矛盾**：`1602A使用说明书.pdf` p.3 的 `DL` 定义写反（“高电平为 4 位总线”）；
  `字符点阵液晶使用手册.pdf` p.10 逐条说明把 1.53 ms 印成 “1.64 µs”；以指令表/`1602A.pdf` p.9 为准。
- `PCA8574 Datasheet.pdf` 是 **PCA8574**（另一型号），**不是**板上 `PCF8574T`，不能用来定地址。
- 40 ms 这个具体数字在 repo 的任何 PDF 中都不存在（最高要求是 15 ms / 4.1 ms）；它来自 Hitachi
  HD44780U 原厂手册。需要引用“40 ms”时请注明出处为原厂手册，而非本 repo 文件。
- 可诊断性建议（非手册要求）：若 `phenomenon.jpg` 的“背光亮 + 花屏”要复现，优先确认 I²C 是否 ACK
  （现在 ACK 全被忽略）以及 PCF8574 是否真的被写入（否则保持 0xFF）。
