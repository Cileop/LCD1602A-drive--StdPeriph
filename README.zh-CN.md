> **背景**：这个仓库最早是一个"求助帖"——屏幕显示乱码、有时能亮有时不亮。

> 而且读忙标志的函数会破坏 I²C 总线。两个问题都已修复，并用主机端仿真验证过。

**第 1 步：把这 6 个文件加进你的 Keil 工程**
（右键分组 → *Add Existing Files…*）：

```
mokuai/MyPCF8574.c     mokuai/MyPCF8574.h
mokuai/MyLCD1602A.c    mokuai/MyLCD1602A.h
```

一般工程里已经带了。

**第 2 步：接 4 根线**

| 转接板 | STM32F103 | 说明 |
|---|---|---|
| `VSS` | `GND` | 必须共地 |
| `VDD` | **`5V`** | 必须 5 V，不要 3.3 V |
| `SDA` | `PB7` | 开漏输出，模块自带 4.7 kΩ 上拉 |
| `SCL` | `PB6` | 开漏输出，模块自带 4.7 kΩ 上拉 |

**第 3 步：写代码**

```c
#include "MyLCD1602A.h"

int main(void)
{
    LCD1602A_Init();
    LCD1602A_ShowString(1, 1, "Hello, world!");
    LCD1602A_ShowString(2, 1, "I2C 0x27 OK");
    while (1)
    {
    }
}
```

**第 4 步：检查结果**

- 屏幕全黑/没反应 → `LCD1602A_IsPresent()` 返回 `0`，查接线、5 V 和 `LCD1602A_LastError()`；
- 有字但很淡 → 这是对比度（`V0` 模拟电压）问题，不是代码，见 [常见问题](#7-常见问题)。

整个集成就是：**6 个文件 + 4 根线 + 3 个函数调用**。

## 1. 特性

| 特性 | 说明 |
|---|---|
| **4 位数据总线** | 转接板只引出 `D4`–`D7`；每个字节拆成两个半字节，各产生一次 `E` 脉冲 |
| **正确的复位序列** | `0x3, 0x3, 0x3 → 0x2 → 0x28 → 0x08 → 0x01 → 0x06 → 0x0C`，上电等 50 ms |
| **自动识别地址** | 扫描 `0x27`（PCF8574）与 `0x3F`（PCF8574A） |
| **ACK 检查** | 每次写都检查从机应答，失败返回错误码而不是静默忽略 |
| **总线恢复** | 上电打 9 个 SCL，防止从机卡死把 SDA 拉低 |
| **不读忙标志** | 用数据手册的固定延时（39 µs / 1.53 ms）代替；总线只有"写"，更简单可靠 |
| **行列定位** | `row = 1..2`、`col = 1..16`，越界自动夹住 |
| **自定义字符** | 8 个 CGRAM 自定义点阵字符 |
| **对比度自检图** | 16 个实心黑块，用来区分"对比度不足"和"字体本身细" |
| **背光控制** | 通过 `P3`，极性可配；硬件常亮的模块此功能无效 |

## 2. 硬件

### 2.1 物料清单

| 器件 | 说明 |
|---|---|
| STM32F103C8T6 开发板 | 例如 "Blue Pill"，72 MHz，3.3 V 逻辑 |
| LCD1602A | 16×2，HD44780 兼容控制器 |
| PCF8574 I²C 转接板 | 4 线模块，地址 `0x27`（PCF8574）或 `0x3F`（PCF8574A） |
| 4 根杜邦线 | `5V`、`GND`、`SDA`、`SCL` |
| 上拉电阻 | 转接板一般自带（4.7 kΩ 到 VDD） |

### 2.2 转接板与 LCD 引脚映射

PCF8574 有 8 个准双向口，常见 4 线转接板的接法：

```
 PCF8574 一个字节 = 同时刷新 P7..P0
 ┌────┬────┬────┬────┬──────┬────┬────┬────┐
 │ P7 │ P6 │ P5 │ P4 │ P3   │ P2 │ P1 │ P0 │
 │ D7 │ D6 │ D5 │ D4 │ 背光 │ E  │ RW │ RS │
 └────┴────┴────┴────┴──────┴────┴────┴────┘
```

| PCF8574 引脚 | LCD1602A 引脚 | 作用 |
|---|---|---|
| `P0` | `RS` | 指令 / 数据选择 |
| `P1` | `RW` | 读 / 写（本驱动恒为 0） |
| `P2` | `E` | 使能，数据在下降沿被锁存 |
| `P3` | 背光三极管 | 有效电平因模块而异 |
| `P4`–`P7` | `D4`–`D7` | 4 位数据 |

### 2.3 与 MCU 的接线

| LCD / 转接板 | STM32F103C8T6 | 说明 |
|---|---|---|
| `VSS` | `GND` | 必须共地 |
| `VDD` | **`5V`** | **必须 5 V**；接 3.3 V 会让字发灰（见 [7.2](#72-字很淡--对比度不够)） |
| `SDA` | `PB7` | 开漏输出，转接板上有上拉 |
| `SCL` | `PB6` | 开漏输出，转接板上有上拉 |

### 2.4 供电与上拉

- **LCD 用 5 V 供电。** HD44780 的对比度需要 `VDD − V0 ≈ 4.2 … 4.8 V`（25 °C），
  3.3 V 供电时物理上达不到，字一定发灰。
- 转接板通常在 SDA/SCL 上各带 **4.7 kΩ 上拉到自己的 VDD**。
- `PB6`/`PB7` 是 **5 V 容忍（FT）** 引脚，驱动里配置为 **开漏输出**，
  所以 5 V 上拉不会倒灌 MCU。
- 杜邦线尽量短，`GND` 一定要接牢——面包板接触不良是"时好时坏"的头号原因。

### 2.5 连接框图

```
 STM32F103C8T6                 PCF8574 转接板                LCD1602A
 ┌──────────────┐              ┌───────────────┐             ┌──────────────┐
 │ PB6  (SCL) ──┼──────────────┤ SCL           │             │              │
 │ PB7  (SDA) ──┼──────────────┤ SDA           │             │              │
 │ 5V  ─────────┼──────────────┤ VDD           │ P0..P2 ─────┤ RS  RW  E    │
 │ GND ─────────┼──────────────┤ GND           │ P4..P7 ─────┤ D4  D5  D6 D7│
 └──────────────┘              │               │ P3 ─────────┤ 背光         │
                               └───────────────┘             └──────────────┘
```


黑块应该是**纯黑**的；发灰/发绿说明对比度电压（V0）偏弱。

## 6. 工作原理

### 6.1 软件 I²C

`PB6`（SCL）和 `PB7`（SDA）配置为 **50 MHz 开漏输出**：
写 1 通过 `BSRR` 释放引脚，写 0 通过 `BRR` 拉低。半个周期 5 µs（约 66 kHz），
在 PCF8574 的 100 kHz 上限之内。每次事务都是：START → 地址 → 数据 → STOP，
并检查 ACK 位。

### 6.2 一个字节怎么变成四根线

因为只接了 `D4`–`D7`，一个 LCD 字节要分**两个半字节**发送：

```
高半字节: [ D7 D6 D5 D4 ]  E 拉高，再拉低（锁存）
低半字节: [ D3 D2 D1 D0 ]  E 拉高，再拉低（锁存）
```

每个半字节是两次 PCF8574 写入：一次带 `P2 (E) = 1`，一次带 `P2 (E) = 0`。
LCD 在 `E` 的**下降沿**锁存 `D7..D4`。

### 6.3 复位序列

上电时 HD44780 处于 **8 位模式**，而数据手册规定的复位流程是：

```
等待 ≥ 40 ms
  → 0x3, 0x3, 0x3      单半字节，仍为 8 位模式
  → 0x2                DL = 0：从这条起进入 4 位模式
  → 0x28               4 位 / 双行 / 5×8 点阵
  → 0x08               关显示（避免初始化过程中闪乱码）
  → 0x01               清屏（等 1.53 ms）
  → 0x06               输入模式：光标右移、屏幕不滚动
  → 0x0C               开显示、关光标
```

**少发 `0x2` 就永远停在 8 位模式**，之后所有指令都会被解释成残缺的 8 位指令——
这正是原代码乱码的根因。

### 6.4 为什么不读忙标志

通过 PCF8574 读忙标志，需要先把 `P4`–`P7` 置 1（准双向口作输入前必须为高），
再读回 `D7`，还要正确发 NACK + STOP；任何一步错了都会搅乱总线。
本驱动改用数据手册给的固定延时（普通指令 39 µs、清屏 / 归位 1.53 ms），
总线只做"写"——LiquidCrystal_I2C 等成熟库也是这么做的。

## 7. 常见问题

### 7.1 乱码 / 时好时坏

**已在本仓库修复。** 根因（详见 [修复说明.md](修复说明.md)）：

1. 原初始化把 `0x38` 送进 4 位发送函数，总线上实际是 `0x3` 然后 `0x8`——
   **从来没有发过 `0x2`**，控制器一直停在 8 位模式。而 `D3`–`D0` 没有接线，
   悬空值决定了结果：读到 `0x0` 时显示一直关着，读到 `0xF` 时恰好误开显示——
   于是"有时能显示、有时不能"。
2. 读忙标志函数用**写地址**去读、没有释放 `P4`–`P7`、读完还多发了一整个字节，
   每写一个字符都搅乱一次总线（仿真统计 56 处协议违规）。
3. 清屏后没等 1.53 ms，上电只等了 25 ms。

### 7.2 字很淡 / 对比度不够

**对比度是模拟量，由 `V0` 电压决定，软件无法调节。**
改代码、换显示内容、开关背光都不会让"黑"变得更黑。

按顺序排查：

**① 用万用表量 VDD（最常见）**

| 实测 VDD | 结论 |
|---|---|
| 5 V | 供电正常，看第 ② 条 |
| 3.3 V | **这就是原因**。`VDD − V0` 最多只有 3.3 V，而 LCD 需要 4.2–4.8 V。改接 5 V |

**② 已经是 5 V：调对比度电位器（V0）**

电位器在转接板朝里的那一面。如果"转接板 + LCD"是黑胶粘死的，它就被夹在两层板之间。
可选办法：

1. **先软化黑胶**——黑胶多半是热熔胶，用吹风机吹热或蘸一点无水酒精让它变软，
   再用塑料片轻轻分开；**不要用金属刀硬撬**，16 脚排针很容易断。
2. **从 16 脚排针第 3 脚（`V0`）引出外接电位器**：在 `V0` 与 `GND` 之间接一个
   10 kΩ 电位器，调到字最黑为止（V0 越低对比度越深）。
3. **换一块背面带可调电位器的模块**——最省事、最安全。

**③ 用自检图判断"黑能有多黑"**

`User/main.c` 里把 `#define LCD_SHOW_CONTRAST_TEST` 改成 `1`，第 1 行显示 16 个实心黑块：

- 黑块**纯黑** → 对比度其实没问题，是 5×8 字体本身比较细；
- 黑块**发灰/发绿** → 确实 V0 偏弱，回到 ① ② 处理。

**为什么调背光没用**

背光改变的是整体亮度："黑"和"白"同比例变化，对比度**比例**不变。
而且不少模块的背光是硬件常亮的（`LCD1602A_Backlight(0)` 也不灭），
软件也没有可调的余地。

### 7.3 完全不亮 / 没有 ACK

1. `VDD` 是不是 5 V，`GND` 是否共地；
2. `SDA→PB7`、`SCL→PB6` 有没有接反或松动；
3. 转接板上有没有 4.7 kΩ 上拉（多数自带）；
4. 地址：PCF8574 是 `0x27`，PCF8574A 是 `0x3F`——驱动会自动扫描；
5. 看 `LCD1602A_LastError()`：`1` 无应答，`2` 未找到器件。

### 7.4 背光

```c
/* mokuai/MyPCF8574.h —— 亮灭相反时改成 0 */
#define PCF8574_BL_ACTIVE_HIGH  1
```

如果改了没反应，说明这块板的背光根本没经过 `P3`（硬件常亮或常灭），属正常现象。

### 7.5 按键与 PB6 冲突

`mokuai/key.c` 把 **PB6 当按键输入**，而 PB6 是 I²C 的 **SCL**，两者会打架；
而且它初始化配的是 GPIOA、读取却用 GPIOB（复制粘贴错误）。
恢复密码锁功能前，按键必须换脚（例如统一用 PA4/PA5/PA6）。

### 7.6 I2C 地址

| 芯片 | 地址（7 位） |
|---|---|
| PCF8574 | `0x27` |
| PCF8574A | `0x3F` |

`LCD1602A_Init()` 会扫描 `0x20–0x27` 和 `0x38–0x3F`，无需手动修改。

## 附录 A — 原驱动的根因

1. **初始化序列**：`MyPCF8574SendByte(0x38, 0, 0)` 会把字节拆成两个半字节，
   总线上是 `0x3` 然后 `0x8`（仿真抓到的字节是 `0x34/0x30` 后跟 `0x84/0x80`）。
   手册要求的 `0x2` 从未出现，`DL` 一直是 `1`，控制器停在 8 位模式。
   `D3–D0` 悬空，于是悬空值决定结果：`0x0` → 显示永远不打开；`0xF` → `0x0F`
   恰好被当成有效指令，显示打开了但 DDRAM 是垃圾。
2. **读忙标志函数**：用**写地址**寻址（`READ_TXNS_0x4F = 0`）、从不释放 `P4–P7`、
   用一个完整字节代替 1 个 NACK、还有没有 STOP 的 repeated START。
   仿真统计 56 处违规。最后的判断也是死代码：
   `Hdata &= 0x0F; Hdata &= 0x80;` 恒等于 0。
3. **时序**：清屏后等了 0 ms（应为 1.53 ms）；上电只等 25 ms
   （模块手册要求 > 4.1 ms，原厂 HD44780U 手册要求 40 ms，驱动现在等 50 ms）。
4. **GPIO**：`GPIOB->CRL = 0x77000000` 把 `PB0`–`PB5` 的配置一起覆盖了。
   现在改用 `GPIO_Init()` 只配置 `PB6`/`PB7`。
5. **背光**：`P3` 从来没被拉高。新驱动显式点亮，并把极性做成可配置。
